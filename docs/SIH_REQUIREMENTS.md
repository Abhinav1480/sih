# SIH 2026 Problem Statement 26176: Requirements Traceability Matrix
## "ORCA - Marine EcOsystem Reasoning with Collaborative Agents"

### 1. Problem Statement Context & Domain
- **Problem Statement ID**: 26176
- **Title**: ORCA - Marine EcOsystem Reasoning with Collaborative Agents
- **Organisation**: Indian Space Research Organisation (ISRO)
- **Department**: Department of Space
- **Category**: Software
- **Theme**: Disaster Management
- **Data stakeholders referenced by the solution**: ISRO / NRSC (Bhuvan, MOSDAC, Bhoonidhi, INSAT, Oceansat-3, SCATSAT, SARAL-AltiKa), Indian National Centre for Ocean Information Services (INCOIS), India Meteorological Department (IMD), MoEFCC (protected areas), Indian Coast Guard.
- **Context**: The problem statement is set by the Department of Space and emphasises satellite Earth Observation throughout; every architectural decision is made to be defensible to an ISRO evaluator. Marine data across Indian oceanic zones (Arabian Sea, Bay of Bengal, Indian Ocean) is scattered across independent scientific services (INCOIS Ocean State Forecasts, PFZ Advisories, OSF high wave alerts, IMD weather and cyclone bulletins, Department of Fisheries regulations, Marine Protected Areas under MoEFCC). Coastal communities, commercial navigators, and marine administrators face critical delays, cognitive overload, and fragmented understanding when planning offshore activities.

### 2. Requirements Traceability Matrix

| Req ID | Official SIH Requirement Category | ORCA Technical Implementation | Verification Method | Implementation Status | Limitations & Assumptions |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **REQ-01** | Natural Language Query Understanding | Generalized intent, entity, coordinate, temporal, and constraint extraction engine in `backend/app/agents/planner.py` with scored intent matching in `backend/app/agents/intent.py` | Unit tests on 30+ unseen queries (`test_generalization_30_queries.py`) plus one test per canonical query (`test_intent_classification.py`) | **VERIFIED** | Supports complex conjunctions, spatial constraints, and multi-parameter filters. |
| **REQ-02** | Collaborative Multi-Agent Architecture | Discrete specialist agents (`OceanAgent`, `WeatherAgent`, `FisheryAgent`, `GeoAgent`, `VesselAgent`, `RiskAgent`, `ReportAgent`) orchestrated via `AgentOrchestrator` | Execution audit log with recorded start/end timestamps and step telemetry | **VERIFIED** | All agents run real asynchronous tasks; no synthetic placeholder timers. |
| **REQ-03** | Authoritative Oceanographic Data Integration | INCOIS Ocean State Forecast, SST, Chlorophyll-a, Swell, Significant Wave Height, and Currents adapters | Tiered provider chain (`backend/app/providers/chain.py`): ISRO → NATIONAL → FALLBACK, tier validated on every value | **PARTIAL** | **Bhuvan WMS is live and unauthenticated** — four ISRO layers in every response. MOSDAC and Bhoonidhi adapters exist but are token-gated and skipped with a stated reason; INCOIS is cache-only. Every *observation* is therefore still `FALLBACK` from a clean checkout. Tide has no provider and is reported unavailable by name. |
| **REQ-04** | Meteorological Data Integration | IMD Weather bulletins, wind speed/direction, precipitation, lightning, cyclone tracks, and storm warnings | Open-Meteo ingestor with structured alert classification; MOSDAC INSAT-3D adapter for lightning/cyclone | **PARTIAL** | **Lightning and cyclone tracking has no working provider** (MOSDAC is token-gated). It is reported unavailable by name and the wind-derived alert level is never presented as a lightning feed. No IMD adapter exists. |
| **REQ-05** | Fisheries & Potential Fishing Zone (PFZ) Intelligence | INCOIS PFZ integration, sea surface temperature thermal fronts, chlorophyll concentration contours, and distance ranking | Spatial filtering within configurable nautical mile / km radii | **PARTIAL** | Ranking and spatial filtering are real; the underlying chlorophyll and SST values are synthetic in DEMO mode and labelled `FALLBACK`. PFZ advisories are decision aids and do not guarantee fish catch. |
| **REQ-06** | Spatial Reasoning & Geofencing | Exact distance, bearing, point-in-polygon, buffer radius, coastal zones, EEZ boundaries, and Marine Protected Areas (MPAs) | GIS engine with Shapely spatial geometry (`backend/app/geospatial/`); ISRO Bhuvan coral reef and mangrove layers as ecologically sensitive zones | **PARTIAL** | Distance, bearing and point-in-polygon are exact and Marine Protected Areas are enforced. Coral reefs and mangroves are shown from ISRO Bhuvan. **International Maritime Boundary Line and EEZ geometry are not present**; those land in BE-05. |
| **REQ-07** | Deterministic Risk & Marine Safety Engine | Multi-factor risk engine computing weighted hazard indices (0-100) based on wave height, wind, swell, storm alerts, and restrictions | Deterministic matrix with rule explanations and transparent factor breakdown (`backend/app/risk/`) | **VERIFIED** | Thresholds are configurable in `risk/thresholds.py`. Factor points sum exactly to the score, and the score is renormalised over the inputs actually observed so a missing feed can never make the sea look calmer. |
| **REQ-08** | Dynamic Visualization & Adaptive UI | Adaptive result interface rendering maps, time series charts, comparison tables, or risk cards dynamically based on question type | UI visual inspection across multiple query archetypes | **VERIFIED** | UI renders only relevant components rather than a fixed static dashboard. |
| **REQ-09** | Evidence, Provenance & Data Freshness | Granular data tracking preserving provider name, dataset ID, measurement unit, coordinate, timestamp, freshness status, and quality index | Provenance record attached to every metric, with `provider_tier` asserted per response (`test_envelope_contract.py`) | **VERIFIED** | Provider and tier propagate from the observation that produced the value; a synthetic value can never be published above tier `FALLBACK`. Badges: `LIVE`, `FORECAST`, `CACHED`, `HISTORICAL`, `DEMO`. |
| **REQ-10** | Multi-Turn Conversational Memory | Conversational session manager retaining spatial context, temporal targets, active entities, and previous analysis results | Multi-turn test suite testing follow-up queries ("What about tomorrow?", "Why?") | **VERIFIED** | Session state persisted in database with full thread history. |
| **REQ-11** | Multilingual Accessibility | Architecture supporting 10 Indian coastal languages (English, Telugu, Hindi, Tamil, Kannada, Malayalam, Marathi, Bengali, Gujarati, Odia) | Multilingual synthesiser and language auto-detector in `backend/app/utils/multilingual.py` | **PARTIAL** | Language is detected and returned as `language`, and summaries are localised from a template vocabulary. **Full vernacular synthesis with marine terminology and localised numerals lands in BE-09.** |
| **REQ-11b** | Stable API Contract | Versioned response envelope in `docs/API_CONTRACT.md` and `backend/app/models/envelope.py`; every response validated against the Pydantic model | `test_envelope_contract.py` validates all eight canonical queries | **VERIFIED** | Contract v1.0.0. Any breaking change requires a version bump and a note to the frontend track. |
| **REQ-12** | Dual Mode Operation (Live & Deterministic Demo) | Environment toggle `ORCA_MODE=LIVE|DEMO`. Demo mode contains consistent geospatial and temporal datasets across Indian waters | Comprehensive test suite executing in Demo mode without network dependencies | **VERIFIED** | Transparent UI badge indicating demo data status when active. |
